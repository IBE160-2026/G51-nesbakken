- (decision) Overall UX direction: simple and playful, NOT a complex route-planning-app feel. First screen should not be a map-heavy control panel. Core ask reduced to three inputs: starting point, available time, topic/interest - Jaunt does the complicated work invisibly behind that. Trip Setup can be conversational/progressive (Jaunt guides through choices one at a time) rather than one big form - user wants both approaches explored, leaning progressive.
- (decision) Starting point: map-based selection, with current-location support eventually (not necessarily V1) - but must not feel like 'just Google Maps'. Time selection must be very quick. Topic selection should feel visual/easy, not a dropdown/list.
- (decision) Route Review: proposed Jaunt shown as a loop on a map AND as a list/cards of actual stops, so user can see what they're getting before approving. Explicit approval required (matches PRD FR-8). Re-Jaunt should be prominent/primary action, not buried - core to the product's 'if you don't like it, get another' value prop. Remove/replace individual stop desired if it fits.
- (decision) Landmark vs hidden-gem preference (PRD FR-4, Open Question 1): user leans toward a pull/scale control (well-known <-> less-known/balanced) but explicitly wants this explored as options in UX rather than decided now.
- (decision) During-walk experience: map + next stop should be easy to access/glanceable. Content (story/fact/notice-prompt/small task) should feel like part of the experience, not a Wikipedia page. Reading/opening content is never required to continue (matches PRD FR-12). Marking a stop Visited/Completed (PRD FR-13) should be a simple explicit interaction - user's suggestion: a 'visited' checkbox - opening the story must NOT auto-mark visited (matches PRD's opened/engaged vs visited/completed distinction).
- (decision) Jaunt character: important to the product's personality. Appears around the experience assisting with prompts/loading/empty states - not a constantly-talking or screen-taking-over presence. User wants their existing visual draft (not yet received) reviewed BEFORE any character/eyes-scaling decisions are made in this UX process.
- (decision) Overall tone: spontaneous, curious, a little quirky, but still easy to understand. AI/routing/source complexity should be invisible to the user by default, while source attribution remains available/visible to those who want to check it (matches PRD FR-20).
- (assumption) Gamification (collectible stickers for visited stops) raised by user as a future idea, explicitly 'a note rather than current discussion' - not in scope for this UX pass, parked for later.
